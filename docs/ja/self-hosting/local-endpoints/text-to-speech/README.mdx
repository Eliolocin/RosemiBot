キャラクターごとの料金を支払ったり、サードパーティの音声APIにオーディオをストリーミングしたりすることなく、自然な音声メッセージとキャラクターのスピーチをマシン上で直接生成します。

TomoriBotは音声をカスタムエンドポイント機能として扱います。ローカルエンジンはボットの外部でHTTPサーバーとして実行され、`POST /synthesize`を実装します。クローンエンジンはテキストと設定されたリファレンスオーディオサンプルを受け取りますが、VoiceDesign対応エンジンは自然言語の命令も受け取ることができます。

## セットアップの流れ

1. 上記のカードからエンジンを1つ選択し、そのラッパーを`servers/tts/`からセットアップします。
2. `/providers`では、`Add New Custom Endpoint`を選択し、API互換性`tts-clone`を使用します。
3. 保存したエンドポイントを選択し、そのモデルドロップダウンを使用して、音声モデル、音声ソースモード、およびスクリプトマークアップを追加します。
4. `/config` > `モデル` > `モデルの切り替え` を開き、登録されている音声モデルを選択します。

## ネットワークアクセス
{/* anchor: network-access */}

TTSローカルサーバーはすべて既定で`127.0.0.1`にバインドするため、同じマシン上のボットからしか接続できません。TomoriBotをDockerや別のマシンで実行する場合は、サーバー側で`TOMORI_TTS_HOST=0.0.0.0`を設定し、ホストのアドレス（例：`http://host.docker.internal:8015`）でエンドポイントを登録してください。

サーバーには認証がありません。ポートに到達できる人は誰でも、あなたのGPUで合成を実行できます。ループバック以外へのバインドは信頼できるネットワーク内に限り、それより外へ公開するサーバーには認証付きのリバースプロキシを前段に置いてください。

各サーバーは専用のポート変数（`CHATTERBOX_PORT`、`QWEN3TTS_PORT`、`IRODORI_TTS_PORT`、`FISH_S2_PORT`、`VOXCPM2_PORT`、`COSYVOICE3_PORT`、`MOSS_TTS_PORT`）を読み込むため、1つの`.env`で複数のサーバーを同時に実行できます。`bun run launch`は起動するサーバーに`.env`を渡しますが、手動で起動したサーバーはシェルの環境変数だけを読み込みます。

## ペルソナボイスの流れ

クローンエンジンの場合、ペルソナごとに1つの音声サンプルを追加して割り当てます。

1. スピーカーが1つあり、BGMのないクリーンなクリップを準備します。各エンジンには、モデルに応じて3 ～ 30秒の最適な長さが記録されています。以下のエンジンごとのガイドに番号が記載されています。
2. [モデル] > `TTSパラメーターと音声` で`/config`を開き、サンプルをアップロードします。あらゆるオーディオ形式が受け入れられます。TomoriBotは最大130秒のモノラルWAVに変換します。
3. エンジンにメリットがある場合は、一致するトランスクリプトを提供します。Fish S2 Proは、保存された参照トランスクリプトをクローン作成リクエストに転送し、VoxCPM2はそれをより忠実度の高い究極のクローン作成に使用します。
4. [ペルソナ] > `音声` で`/config`を開き、ペルソナと音声サンプルを選択します。

130秒のアップロード上限は、TomoriBotによって強制されます。各エンジンはクリップの送信時に独自の基準オーディオ制限を適用しますが、それらの制限は十分に異なるため、あるエンジンに適したクリップが別のエンジンで拒否されたり、部分的に無視されたりする可能性があります。長いクリップをアップロードする前に、エンジンのガイドを確認してください。

アップロードサイズの制限と期間の上限は独立しており、サイズチェックが最初に実行されます。非圧縮WAVはステレオ44.1 kHzとして1分あたり約10 MBのコストがかかるため、130秒のDAWエクスポートは約22 MBになり、同じクリップの圧縮エクスポートは簡単に収まるのに大きすぎるとして拒否される可能性があります。`SPEECH_SAMPLE_MAX_MB`は、そのサイズ制限を引き上げます (デフォルトでは10 MB)。長いリファレンスクリップの場合は、WAVではなくFLAC、MP3、またはOGGとしてエクスポートします。TomoriBotは、保存する前に、受け入れられた形式を22.05 kHzのモノラルWAVに変換します。そのため、圧縮アップロードの品質にコストはかかりません。

Qwen3-TTS、MOSS-VoiceGenerator、IrodriTTS、またはVoxCPM2 VoiceDesignの場合は、オーディオサンプルをスキップし、`/config`の [ペルソナ] > `音声` を使用して、ペルソナの自然言語音声説明を保存します。CosyVoice 3は、参照サンプルでクローンモードを使用し、`voice_instructions`を介した1回限りの配信指示を受け入れます。

ElevenLabsユーザーは、`/providers`で`新しいプロバイダーを追加`および`ElevenLabs`を選択する必要があります。音声と文字起こしのエンドポイントを一緒に登録します。

TomoriBotは、合成前に、生成された音声スクリプトから`:pepega:`や`<:pepega:123456789012345678>`などのDiscordカスタム絵文字構文を削除します。Unicode絵文字も、音声エンドポイントがIrodriTTS用の絵文字マークアップを使用しない限り、削除されます。ブラケットタグは、スクリプトマークアップが`ブラケットタグ`に設定されている場合、Chatterbox TurboやFish S2 Proなどのエンドポイントに対して保持されます。

VoxCPM2は`プレーン`スクリプトマークアップを使用します。その音声デザインと話し方のコントロールは、TomoriBotの`instruct`フィールドを通過し、VoxCPM2ラッパーはそれらをモデルのネイティブの括弧で囲まれた自然言語コントロール構文に変換します。

CosyVoice 3も`プレーン`スクリプトマークアップを使用します。トランスクリプトに裏付けられた参照はゼロショットクローニングに、トランスクリプトなしの参照はクロスリンガルクローニングに、`voice_instructions`は命令条件付きパスにマッピングされます。CosyVoice命令が発話全体に適用されるため、インライン括弧タグは削除されます。
