Alibabaの [CosyVoice 3](https://github.com/QwenAudio/CosyVoice) を使用して、指示ベースの感情表現により自然な多言語キャラクターの声を合成します。

CosyVoice 3は、9つの言語と18以上の中国語の方言にわたるゼロショットおよびクロスリンガル音声クローン作成を提供します。TomoriBotは、公式ランタイムを`servers/tts/cosyvoice3/`でラップして、標準の`POST /synthesize`音声インターフェイスを公開します。バンドルされたインストーラーは、デフォルトで量子化されていない公式の`FunAudioLLM/Fun-CosyVoice3-0.5B-2512`モデルになり、16 GBのVRAM内で実行されます。

## 対応機能

現在のCosyVoice 3リリースは以下をサポートしています。

- 中国語、英語、日本語、韓国語、ドイツ語、スペイン語、フランス語、イタリア語、ロシア語
- 18以上の中国語の方言とアクセント
- ゼロショット音声クローン作成
- 多言語および言語を越えた音声クローン作成
- 言語、方言、感情、話す速度、音量に関する自然言語による指示
- `[breath]`および`[laughter]`を含むアップストリームランタイムのきめ細かい制御
- アップストリームランタイムでのテキスト入力およびオーディオ出力ストリーミング

公式のCosyVoice 3の例には、日本語に関する注意事項が1つ含まれています。日本語のテキストはカタカナに変換されて表示されます。日本語はサポートされている言語ですが、通常の日本語正書法で発音が悪い場合は、合成テキストをカタカナに変換することが上流で推奨される回避策です。

## TomoriBotがリクエストをどう対応させるか

ラッパーは標準の`tts-clone`フィールドを受け入れます。

- `text`
- `ref_audio`
- `ref_text`
- `instruct`
- `language`

次のようにリクエストをCosyVoice 3推論関数にルーティングします。

| リクエスト | CosyVoice 3パス |
|---|---|
| 参考音声 + トランスクリプト | `inference_zero_shot` |
| トランスクリプトなしの参考音声 | `inference_cross_lingual` |
| `instruct`または明示的な`language` | `inference_instruct2` |

最高のクローン作成品質を得るには、参照オーディオとそれに一致するトランスクリプトの両方を提供してください。CosyVoice 3の現在の命令APIは、リファレンストランスクリプトを受け入れずにリファレンスオーディオを条件としているため、`instruct`を含むリクエストは公式の`inference_instruct2`パスに切り替わります。

### スタイルと感情の制御

`プレーン`マークアップを使用してエンドポイントを登録します。配信方向は、エンドポイントのグローバル`voice_instructions`フィールドに属します。任意のインライン括弧タグは、`[happy] Hello. [sad] Goodbye.`など、矛盾する命令を引き起こす危険があるため避けられます。ネイティブ`[breath]`タグと`[laughter]`タグは、TomoriBotがエンジン固有のタグ検出をサポートするまで延期されます。

`/synthesize` `instruct`フィールドは、CosyVoice 3の命令コンディショニングに渡されます。例には、`sound relieved but still tired`、`speak as quickly as possible`、または`speak quietly with restrained excitement`が含まれます。

## ストリーミング

CosyVoice 3は、アップストリームの双方向ストリーミングをサポートします。アップストリームベンチマークでは、最適化されたセットアップでの初期オーディオレイテンシーが約150ミリ秒であるテキスト入力およびオーディオ出力ストリーミングが報告されています。

TomoriBotの音声インターフェイスは、Discord音声メッセージに対する単一の完全な音声応答を期待するため、ラッパーは完全なWAVファイルを返し、デフォルトのアップストリーム推論を`stream=False`に設定します。`COSYVOICE3_UPSTREAM_STREAM=1`は、アップストリームストリーミング動作を直接ベンチマークする場合にのみ設定します。TomoriBotレイテンシは変わりません。

## ハードウェア

推奨ハードウェア:

- 16 GB VRAMを搭載したNVIDIA GPU
- Python 3.10
- CUDA 12と互換性のあるNVIDIAドライバー
- `git`
- 音声サンプルの正規化用の`ffmpeg`
- オーディオ互換性の問題が発生した場合のLinux上の`sox`および`libsox-dev`

0.5Bパラメータモデルは、量子化なしで16 GB VRAMに簡単に収まります。チェックポイントのダウンロードには、フロー モデル、音声トークナイザー、テキストモデル、強化学習の重みが含まれており、約10 GBのディスク容量とPythonの依存関係が必要です。

CPU推論は技術的にはアップストリームでサポートされていますが、Discord音声対話には遅すぎます。

## インストール

### LinuxおよびWSL2 (推奨)

TomoriBotリポジトリルートから:

```bash
bash servers/tts/cosyvoice3/install-cosyvoice3.sh
servers/tts/cosyvoice3/.venv/bin/python servers/tts/cosyvoice3/server.py
```

または、構成されたサーバーとTomoriBotを一緒に起動します。

```bash
bun run launch --cosyvoice3
```

インストーラー:

1. `QwenAudio/CosyVoice`をチェックアウトし、`074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc`を再帰的に`servers/tts/cosyvoice3/CosyVoice/`にコミットします。
2. `servers/tts/cosyvoice3/.venv`を作成します。
3. アップストリームのCosyVoice要件とラッパーの依存関係をインストールします。そして
4. ハグフェイスリビジョン`29e01c4e8d000f4bcd70751be16fa94bf3d85a18`の`FunAudioLLM/Fun-CosyVoice3-0.5B-2512`を`CosyVoice/pretrained_models/Fun-CosyVoice3-0.5B/`にダウンロードします。

スクリプトを再実行すると、これらの固定されたリビジョンが維持されます。インストーラは、コミットされていないローカル変更でチェックアウトを上書きすることを拒否します。

アップストリーム要件では、CUDA 12.1パッケージを含むPyTorch 2.3.1、Linux上にCUDA 12 ONNXランタイムパッケージ、およびLinux上にTensorRT 10.13パッケージをインストールします。GPUで新しいPyTorchビルドが必要な場合は、セットアップの完了後に、互換性のあるPyTorchビルドを仮想環境内にインストールします。

### Windows PowerShell

ネイティブWindowsはベストエフォートパスとして提供されます。

```powershell
.\servers\tts\cosyvoice3\install-cosyvoice3.ps1
.\servers\tts\cosyvoice3\.venv\Scripts\python.exe servers\tts\cosyvoice3\server.py
```

WindowsでNVIDIA GPUを使用するには、WSL2を強く推奨します。アップストリーム要件ではWindowsにCPUのみのONNXランタイムをインストールしますが、LinuxとWSL2はGPUアクセラレーションパッケージをインストールします。

## TomoriBotへの登録

`/providers`を実行し、`新しいカスタムエンドポイントを追加`を選んで、音声エンドポイントを次のように設定します。

- 機能: 音声
- API互換性: `tts-clone`
- エンドポイントURL: `http://127.0.0.1:8017`
- 音声ソースモード: 音声クローン
- スクリプトマークアップ形式: プレーン
- 指示の対応: 有効

接続を保存したら、それを選択して音声モデルを追加します。分かりやすいモデルコードとしては`Fun-CosyVoice3-0.5B-2512`が挙げられます。

続いて`/config` > モデル > モデルの切り替えを開き、CosyVoice 3の音声エンドポイントを有効化してください。

## ペルソナ音声の割り当て

ゼロショット音声クローンの場合:

1. 1つのスピーカーと最小限のバックグラウンドノイズで、きれいな3 ～ 30秒のオーディオクリップを準備します。
2. [モデル] > `TTSパラメーターと音声` で`/config`を開き、サンプルをアップロードします。
3. 可能な場合は、一致するトランスクリプトを入力します。CosyVoice 3は、このトランスクリプトをゼロショットクローン作成のプロンプトプレフィックスとしてトークン化します。音声の最初の30秒を説明する必要があります。
4. [ペルソナ] > `音声` で`/config`を開き、サンプルをペルソナに割り当てます。

CosyVoiceは、30秒のプロンプトウィンドウを強制します。上流のエンジンはオーディオが30秒を超えるとエラーを生成しますが、TomoriBotのラッパーはクリップを最初の30秒まで自動的にトリミングし、そのトリミングをコンソールに記録します。

スピーカーの埋め込みとプロンプト音声トークンは冒頭の30秒から計算されるため、30秒を超えるクリップには音声の詳細が追加されません。きれいなクリップを10 ～ 20秒間使用すると、正確な位置合わせが確実に行われます。

言語間の複製がサポートされています。参照話者は、生成されたテキストとは異なる言語を話すことができます。参照トランスクリプトが提供されない場合、ラッパーはリクエストをCosyVoice 3の専用のクロスリンガルエンジンパスにルーティングします。

## `/generate voice-message`でテストする

`/generate voice-message`を使用すると、自動チャットトリガーを待たずに合成をテストできます。ペルソナに割り当てられたサンプルを使用してテストすることも、そのトランスクリプトを含む1回限りのクリップをアップロードすることもできます。

感情と表現をガイドするには、モーダルに方向を入力するか、ペルソナプロンプトに`voice_instructions`を入力させます。話し言葉は平易な会話として残しておきます。インラインスタイルタグは合成前に削除されます。

## 環境変数

| 変数 | デフォルト | 目的 |
|---|---|---|
| `COSYVOICE3_MODEL_DIR` | `CosyVoice/pretrained_models/Fun-CosyVoice3-0.5B` | ローカルチェックポイントディレクトリ |
| `TOMORI_TTS_HOST` | `127.0.0.1` | ラッパーバインドアドレス。[ネットワークアクセス](/ja/self-hosting/local-endpoints/text-to-speech/#network-access)を参照してください。|
| `COSYVOICE3_PORT` | `8017` | ラッパーポート |
| `COSYVOICE3_UPSTREAM_STREAM` | `0` | CosyVoiceの内部ストリーミングジェネレーターを有効にする |
| `COSYVOICE3_SPEED` | `1.0` | 上流の推論に渡されるグローバル数値速度乗数 |
| `COSYVOICE3_DEFAULT_INSTRUCT` | 空の | リクエストで指示が提供されない場合に追加されるオプションの指示 |
| `COSYVOICE3_FP16` | `0` | 公式ランタイムにfp16モードを使用するよう依頼する |
| `COSYVOICE3_LOAD_TRT` | `0` | 適切に準備されている場合は、アップストリームのTensorRTロードを有効にします |
| `COSYVOICE3_LOAD_VLLM` | `0` | 個別の依存関係がインストールされている場合にアップストリームvLLMロードを有効にする |

デフォルトでは、TensorRT、vLLM、およびfp16は無効のままです。標準のPyTorchランタイムは、追加のランタイム依存関係なしで16 GB GPU上で快適に実行されます。

## パフォーマンスとモデルの種類

### 既定: ベースの`Fun-CosyVoice3-0.5B-2512`

これは、TomoriBotの推奨デフォルトです。高いスピーカー類似性を提供し、すべてのCosyVoice 3クローン作成および命令モードをサポートし、16 GB GPUでは量子化を必要としません。

### 強化学習の重み

チェックポイントパッケージには、ベースウェイトと一緒に`llm.rl.pt`が含まれています。RL重み付けによりコンテンツのエラー率が低下し、話者類似性ベンチマークでは基本重み付けのスコアがわずかに高くなります。ペルソナ音声の忠実度が優先されるため、ラッパーのデフォルトは`llm.pt`です。

上流のローダーは`llm.pt`を予期します。デフォルトのファイルを変更せずにRL重みをテストするには、モデルディレクトリを複製し、コピー内で`llm.rl.pt`の名前を`llm.pt`に変更し、コピーしたフォルダーに`COSYVOICE3_MODEL_DIR`を設定します。

### vLLMとTensorRT

CosyVoice 3は、オプションのvLLMおよびTensorRTランタイムをサポートします。アップストリームでは、V1エンジンを備えたvLLM 0.11.x+ と、レガシーとしてのvLLM 0.9.0が文書化されています。これらのライブラリにはCUDAと依存関係のバージョン要件が厳格に導入されているため、TomoriBotはデフォルトではそれらをインストールしません。
