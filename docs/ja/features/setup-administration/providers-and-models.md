TomoriBotは、組み込みモデルをホストするのではなく、外部AIプロバイダーに接続します。Google Gemini、OpenRouter、NovelAIなどのホスト型サービスに接続したり、ローカルのセルフホスト型エンドポイントをポイントしたりできます。チャットを開始するには、少なくとも1つのプロバイダーが必要です。

## APIキー
<!-- anchor: api-keys -->

初回セットアップ中に`/setup`を使用してプロバイダー キーを追加するか、後で`/providers`から`+ Add new Provider`を選択してプロバイダー キーを追加します。キーは保存時に暗号化されるため、サーバー管理者を含む誰もキーを読み取ることはできません。

`/setup`は、他の何よりも先に応答がどのようにモデルに到達するかを尋ね、その答えによって収集されるものが決まります。

| モード | 収集するもの |
|---|---|
| AIプロバイダー (推奨) | カタログのプロバイダーとそのAPIキー。ドラフトとして検証および暗号化されます。|
| カスタムエンドポイント (詳細) | ウィザード内に登録されたエンドポイント接続と1つのテキストモデル。[カスタムエンドポイント](#custom-endpoints) を参照してください。|
| ユーザー BYOK (ギルドのみ) | 何もありません: ワークスペースは独自のプロバイダーを保持しないため、メンバーは個人的なプロバイダーを提供する必要があります。|

`セットアップを完了`を押すまで、データベースには何も書き込まれません。ウィザードが放棄されたか期限切れになった場合、ワークスペースの既存のプロバイダー行はそのまま残ります。既存のキーを置き換えるには、`/providers`を使用します。これは、`/setup`はすでに構成されているワークスペースでは実行されないためです。

各プロバイダーには独自の鍵生成手順があります。`/help`で、`セットアップ`、次に`APIキーの取得`を選択し、ステップバイステップのウォークスルーのためにプロバイダーを選択するか、次の開始点を使用します。

| プロバイダー | 注意事項 | 鍵を入手する |
|---|---|---|
| Googleジェミニ | 無料利用枠では、すべての機能が実行されます。最初のセットアップを推奨します。| [AIスタジオ](https://aistudio.google.com/apikey) |
| OpenRouter | 1つのキーで多くのモデル (一部は無料)。| [OpenRouterキー](https://openrouter.ai/settings/keys) |
| NovelAI | サブスクリプション; 無修正のストーリーテリングとロールプレイ (テキストのみ)。| [NovelAI](https://novelai.net/) |
| ディープシーク | 従量課金制推論モデル。| [ディープシーク](https://platform.deepseek.com/api_keys) |
| NVIDIA NIM | ホストされたテキスト、埋め込み、および画像。| [NVIDIAビルド](https://build.nvidia.com/) |
| 人間的 | クロードモデルはAPI (クロードコードではありません) を介して作成されます。| [人外](https://console.anthropic.com/) |
| Z.ai | GLMファミリー。⚠️ ToSにより、使用はコーディングとエージェントのシナリオに制限されます。| [Z.ai](https://z.ai/) |
| Vertex AI | `gcloud` ADC経由のGoogleクラウド (ローカルで実行または開発セットアップに最適)。| 以下を参照してください |
| Vertex AI Express | GoogleクラウドAPI-キー BYOK (プレビュー、Geminiサブセット)。| [エクスプレスモード](https://console.cloud.google.com/expressmode) |
| カスタム | 任意のOpenAI互換エンドポイント (Ollama、vLLM、LiteLLMなど)。| [カスタムエンドポイント](#custom-endpoints) を参照してください。|

:::caution
APIキーを他の人と決して共有しないでください。`/providers`の`エンドポイントを編集`アクションからカスタムエンドポイントのベアラー認証トークンを追加または置換します。
:::

Vertex AIは、保存されたシークレットではなく、アプリケーションのデフォルト認証情報 (ADC) を使用して認証します。ローカルホスティングの場合、ADCは`gcloud`から取得できます。ホスト型展開では、ワークロードIDまたはサービスアカウントを使用する必要があります。AI Studio APIキーだけでは完全なVertex AIを認証しません。選択したGoogleクラウドプロジェクトには課金とVertex AI APIが有効になっている必要があり、ホストIDにはVertexアクセスが必要です。セットアップガイドは、`/help`の`API Keys`ページのGoogle Vertex AIから入手できます。

Googleでサポートされるプロバイダーのセットアップは、認証されたモデルリストエンドポイントを通じて資格情報を検証します。テキストは生成されず、現在カタログのデフォルトとしてマークされているチャットモデルにも依存しないため、廃止されたデフォルトモデルによって有効な認証情報の保存が妨げられることはありません。

### オプション：Brave Searchキー

Brave SearchはAIプロバイダーとは別のもので、画像、ビデオ、ニュースの結果を使用してWeb検索を強化します。`/providers`に設定します。⚠️ Braveには月額5ドルの無料クレジットが含まれているため、予期せぬ請求を避けるために、Braveダッシュボードで5ドルの使用制限を設定してください。

## モデルの選択

`/providers`を使用して、サーバー資格情報、モデルカタログ、エンドポイント登録を管理します。次に、`/config` > `モデル` > `モデルの切り替え` を使用して、サーバーのすべてのメンバーが使用する共有機能の割り当てを選択します。どちらのコマンドにもサーバー管理権限が必要です。

個々のメンバーは、`/personal providers`で自分の認証情報とカタログを管理し、`/personal config`で個人モデルを選択します。個人設定は、TomoriBotを使用するすべてのサーバーに適用されます。ユーザー設定については、[個人設定](/ja/features/knowledge/personalization/#your-own-providers)を参照してください。

パネルには`サーバープロバイダー`および`個人プロバイダー`というタイトルが付いているため、開くと所有権が明確になります。

`/config` > `モデル` > `モデルの切り替え` で、8つの機能スロットにわたってモデルとエンドポイントを割り当てることができます。

- **テキスト**: メインのチャットモデル。
- **ビジョン**: チャットモデルが画像を読み取ることができない場合に画像を読み取ります。
- **埋め込み**: [ドキュメントナレッジベース](/ja/features/knowledge/memory/#document-knowledge-base-rag) を強化します。
- **標準イメージ**: 標準イメージの生成 ([イメージ生成](/ja/features/capabilities/media-generation/image-generation/) を参照)。
- **NovelAIイメージ**: NovelAIイメージの生成。
- **ビデオ**: ビデオの生成。
- **TTSエンドポイント**: テキスト読み上げ音声エンドポイント。
- **STTエンドポイント**: speech-to-textオーディオトランスクリプションエンドポイント。

最初の6つのスロットはモデルカタログレコードを選択します。TTSスロットとSTTスロットは、代わりにワークスペーススコープのエンドポイントを選択し、モデル列を書き込むのではなく、選択したエンドポイントをアクティブにします。これらのエンドポイントを`/providers`に登録および編集します。`/personal config`は6つのパーソナルモデルルーティングスロットを保持しますが、パーソナルTTS/STTエンドポイントセレクターは含まれません。

`/providers`では、自動フェイルオーバーとロードバランシングのためのバックアップキーを管理することもできます。

## 判定モデル
<!-- anchor: decision-models -->

判定モデルは、`/providers` および `/personal providers` における独立したカテゴリです。型付きの述語に対して確率で回答します。登録を行っても、アクティブなチャットモデルの変更、調整の確立、または応答レビューのスキップの有効化は行われません。これらのパネルでは、まだ判定モデルの選択は行われません。

OpenRouterはサポートされているネイティブプロバイダーです。キーを保存し、モデルのドロップダウンを開いて `+ 判定モデルを追加` を選択します。検証済みの判定カタログからIDを入力します。グローバルカタログには `typesafe/jev-1.13` が含まれます。追加の登録は、そのサーバーまたは個人の所有者に属します。ネイティブの検出により、ドキュメントに記載された入力制限と価格が提供されます。チャットカタログでは判定サポートを確立できません。

カスタムサービスの場合は、`カスタムエンドポイントを追加` を選択し、`API互換性` で `System One互換` または `OpenAI Decisions互換` を選択します。APIのベースURLとオプションのBearer資格情報を保存します。そのモデルドロップダウンで `+ 判定モデルを追加` が提供され、そのプロトコルが継承されます。ドキュメントに記載されたモデルIDと入力トークン制限（512以上）を入力します。Jev、Laya、KevはSystem One互換を使用します。既存のチャット互換およびOllamaネイティブのエンドポイントでは、このアクションは提供されません。

純粋なオリジンは `/v1` に正規化されます。明示的なバージョンとゲートウェイのプレフィックスはそのまま維持されます：`https://decision.example.invalid/gateway/v1` は、System Oneの場合は `/gateway/v1/systemone`、OpenAI Decisionsの場合は `/gateway/v1/decisions` を呼び出します。到達可能性は会話データを送信せずに `GET <stored-base>/models` を使用します。モデルの機能を保証するものではありません。検出によって必要な機能メタデータを確立できない場合、カスタムモデルはサービスドキュメントから手動で登録されます。

保存された判定登録を開いて編集します。カスタム編集では、正確なモデルとエンドポイントのIDが保持されます。接続と資格情報を保持したまま削除するには、`登録アクション` で `この判定登録を削除` を選択します。親プロバイダーまたはエンドポイントを削除すると、その所有者の登録が削除されます。他の所有者は共有エントリを保持します。モデルリストは、既存のページコントロールを使用して、18個の編集可能な登録の後にページ分割されます。

プロバイダーの登録と資格情報は、ペルソナ/設定のエクスポートおよびインポートの対象外です。設定のリセットでは保存された登録が保持されます。親の削除によって明示的にクリーンアップされます。

## カスタムエンドポイント
<!-- anchor: custom-endpoints -->

カスタムエンドポイントを使用すると、セルフホステッドサービスまたはプロキシバックドサービス (Ollama、LM Studio、LiteLLM、vLLM、ComfyUI、ローカルTTS/STT) をラベル付きプロバイダー バンドルとして登録できます。

- **サーバー スコープ**: ワークスペースエンドポイントの登録と編集のために`/providers`を開きます。
- **個人のスコープ**: 個人モデルカタログの`/personal providers`を開きます ([パーソナライゼーション](/ja/features/knowledge/personalization/#your-own-providers) を参照)。個人の音声エンドポイントは`/personal config`から選択されません。

ラベルはユーザー向けのメニュー名であり、1つのエンドポイントURLを共有する場合、機能を1つのバンドルの下にグループ化します。リモートサービスには決して送信されません。異なるURLから提供される機能には、個別のラベルが必要です。

カスタムエンドポイントを追加するには:

1. `/providers`で、`Add New Custom Endpoint`を選択します。
2. API互換性を選択し、接続を保存します。保存すると、モデルを登録せずに、そのプロトコルでサポートされる機能が準備されます。
3. 新しいエンドポイントを選択し、そのモデルドロップダウンを使用して正確なモデルコードと機能を登録します。モデルを追加すると、その機能が有効になります。
4. 同じドロップダウンを使用して、さらにモデルを接続したり、既存の登録を編集したりできます。テキストモデルはその形式で独自の機能を宣言し、イメージモデルはサポートする要求モードを宣言します。

TTSおよびSTTの場合、`/providers`でエンドポイントとそのモデルを登録し、`/config` > `モデル` > `モデルの切り替え`でエンドポイントを選択してアクティブ化します。これらの音声スロットは、モデルカタログエントリではなくエンドポイントを選択します。

API互換性は、サービスが実装するリクエストパスとペイロードを決定するため、接続がどの機能スロットを準備するかも決定します。プロトコルはエンドポイントURLだけからは確実に推論できないため、これらのスロットの正確なモデルを登録することは別の手順になります。

`/setup`の`カスタムエンドポイント（上級者向け）`モードは、ウィザード内で同じ2つのステップを実行します。`接続を設定`は、到達可能性チェックの背後にあるAPI互換性、ラベル、URL、およびオプションの認証トークンを保存し、`テキストモデルを設定`は正確なテキストモデルとその機能宣言を登録します。接続が検証されるまでモデルボタンは無効のままで、宣言はAPIの互換性に依存するため、接続を再保存するとモデル宣言がクリアされます。`セットアップを完了`を押すと、ウィザードは接続、保存されたプロバイダー、モデル、アクティブモデルの行をまとめて作成します。ウィザードはテキストモデルのみを登録します。画像、ビデオ、TTS、およびSTTの機能が`/providers`に登録されます。

OpenCode Go (`https://opencode.ai/zen/go/v1`) とOpenCode Zen (`https://opencode.ai/zen/v1`) は、OpenAI互換のカスタムエンドポイントとして機能します。TomoriBotは、チャネルとペルソナのハッシュから導出された必要な会話ごとのセッションIDをボットに送信するため、Discord IDがボットから離れることはありません。

ローカルサーバーの実行に関する完全なチュートリアルについては、以下を参照してください。

- [セットアップ: ローカルLLM](/ja/self-hosting/local-endpoints/setup-local-llm/): Ollama、KoboldCPP、LM Studio、vLLM、LiteLLM。
- [セットアップ: ComfyUI](/ja/self-hosting/local-endpoints/setup-comfyui/): ローカルの画像とビデオの生成。
- [セットアップ: ChatMock](/ja/self-hosting/local-endpoints/setup-chatmock/): ChatGPTアカウントまたはCodex CLI。

### 画像生成

| プロバイダー | テキストから画像へ | 画像から画像へ | 修復 | 注意事項 |
|---|---|---|---|---|
| Google | ✅ | ✅ | - | - |
| OpenRouter | ✅ | ✅ | - | - |
| NovelAI | ✅ | ✅ | ✅ | 他のプロバイダーと組み合わせることができます |
| エヌビディア | ✅ | - | - | テキストから画像への変換のみ。参照画像は無視されます |
| Z.ai | ✅ | - | - | - |

これらは、プロバイダーのイメージモデルの開始時のデフォルトです。NovelAIは、このテーブルではなく独自のパイプラインを通じて実行されます。`/providers`を通じてイメージモデルを登録すると、そのモデル独自のモードを宣言できます。これにより、ComfyUIワークフローまたはAPIがマスクされた編集をサポートするプロバイダー モデルで修復を有効にすることができます。宣言していないモデルは、上記のデフォルトに従い続けます。モデルがサポートするもののみを宣言します。TomoriBotは、選択したモード用のツールのみを提供し、サポートされていないモードは生成時に失敗します。
