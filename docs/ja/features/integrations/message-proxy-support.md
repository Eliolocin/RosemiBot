メッセージプロキシ対応は、外部のDiscord Botが元のメッセージを削除し、Webhook経由で再投稿する仕組みにTomoriBotを対応させる機能です。

## サービスを選ぶ

`/personal message-proxy service:pluralkit` または `/personal message-proxy service:pluralbuddy` を実行します。プロキシ処理を無効にするには `service:none`（「なし」と表示）を選択します。この設定は元のメッセージを送るDiscordアカウントの個人設定で、サーバーをまたいで適用されます。

TomoriBotがオルタの最初の検証済みメッセージを検出した後は、`/personal config identity:` でそのプロフィールを、`/personal memories identity:` でその記憶を編集できます。オートコンプリートには、プロキシ処理が無効の場合でも両サービスで保存されたアイデンティティが表示されます。アカウントのインターフェース、プライバシー、モデルの設定はホストアカウントに残ります。TomoriBotで設定したニックネームは消去されるまで維持され、それ以外の場合は検証済みメッセージのたびにサービスの表示名へ更新されます。メンバーやプロフィールの詳細については[PluralKitサポート](/ja/features/integrations/pluralkit-support/)をご覧ください。

## 安全性のための検証

TomoriはWebhookの名前やアバターからアイデンティティを割り当てることは決してありません。選択したサービスが再投稿ID、ホストアカウント、および安定したオルタIDを検証する必要があります。PluralKitは元のメッセージも正確に特定するため、TomoriBotはそのトリガー判定と返信先を引き継ぐことができます。PluralBuddyはその元のIDを提供しません。TomoriBotは同じホストとチャンネルの最近のメッセージをベストエフォートで照合します。再投稿が元の待機時間を超えて届いた場合や複数の元メッセージが重なった場合は、無視されるか2回目の返信が発生することがあります。検証に失敗した場合や競合した場合は、アイデンティティが作成されることはありません。

その理由から、Tupperboxは現在選択肢として提供されていません。公開ドキュメントにはプロキシ機能の説明がありますが、TomoriBotが安全に利用できる公開の権威あるメッセージ証明APIは記載されていません。

## メッセージの短い待ち時間

サービスを選択すると、Tomoriはアカウントから送られた通常のサーバーメッセージを処理する前に少し待ちます。この間にサービスが削除と再投稿を行えます。プロキシされなかったメッセージは待機後に続行されます。PluralKitの再投稿は元のトリガー判定と返信先を引き継ぎます。PluralBuddyは検証された再投稿内容とベストエフォートの最近メッセージ照合を使用します。

セルフホスト環境では `MESSAGE_PROXY_WAIT_MS` でこの仕組みを調整できます。PluralKit APIのタイムアウトや任意トークンなど、サービス固有の通信設定は別に管理されます。PluralBuddyのメッセージ照合には、デプロイのOAuthアプリ認証情報（`PLURALBUDDY_CLIENT_ID` および `PLURALBUDDY_CLIENT_SECRET`）が必要です。個々のユーザーがトークンを提供する必要はありません。現在のアダプターは `pluralbuddy.app` のみを照会し、セルフホストされたPluralBuddyインスタンスはサポートされていません。
